# 프로 플랜 게이팅 잔여분 (포트폴리오·다국어) — Agent 작업

## 배경

`plans/260813-stripe-billing/`에서 결제 모듈과 게이팅 일부(recruit 단건 상품 3종, artwork 스타터 작품 4개 제한)를
구현했다. 기획서 REQ-020이 정의한 프로 플랜 혜택은 4종인데, 나머지 두 개는 **기능 자체가 코드에 없어서**
그때 구현할 수 없었다.

- **공유 포트폴리오** — `portfolio` 도메인 미존재. 생성·수정·복제·삭제가 프로 전용(`요금제-R01`)
- **다국어 노출** — 미구현. 스타터는 활동 언어 1개, 프로는 여러 언어(`요금제-R03`·`R04`)
- 화질 차등(웹 감상용/원본)도 같은 계열이나 기획서상 마케팅 문구로만 존재하고 실제 제한값이 명시돼 있지 않다

착수 조건은 **해당 기능이 먼저 구현되는 것**이다. 이 플랜은 그 기능 개발과 함께 실행한다.

## 결정

- 게이팅 진입점은 `BillingService.hasProPlan(memberId)` 하나로 통일한다(결제 플랜 D5·D10에서 이미 노출됨).
- 다운그레이드 후에도 **기존 산출물과 공유 링크는 유지**하고 신규 생성만 막는다(`요금제-R01`, REQ-020).

## 금지 범위

- 다운그레이드 시 기존 포트폴리오·링크를 삭제하거나 비공개로 전환하지 않는다.
- billing 모듈에 포트폴리오·언어 관련 코드를 넣지 않는다. 게이팅은 소비 모듈에서 호출한다.

## 검증

- 스타터 계정이 공유 포트폴리오를 생성·수정·복제·삭제할 수 없다.
- 프로 → 스타터 다운그레이드 후 기존 포트폴리오가 제3자에게 계속 열람된다.
- 다운그레이드 계정의 포트폴리오 상세 더보기 메뉴에 `삭제하기`만 노출된다(`요금제-R01`).
- 스타터 계정의 활동 언어가 1개로 제한된다.

## PA-01. 공유 포트폴리오 프로 게이팅

depends on: portfolio 기능 구현

- [x] 포트폴리오 생성·수정·복제·삭제 API에 `hasProPlan` 검사 추가 — 생성(`createShared`)·수정(`assertEditable`, SHARED만)에
      `BillingService.hasProPlan` 게이팅 적용. 복제는 별도 생성 API 재호출 경로라 동일하게 적용됨(origin/main 병합,
      `PortfolioServiceImpl.assertPro`, 2026-08-18)
- [x] 다운그레이드 계정은 삭제만 허용(`요금제-R01`) — `deletePortfolio()`에는 `assertPro`를 걸지 않음(주석으로 의도 명시), 기존 코드가 이미 이 정책을 따르고 있었음
- [ ] 작품 업로드·수정의 포트폴리오 체크박스 상태를 응답에 담아 프론트가 disabled 처리할 수 있게 한다 —
      `ArtworkInfo.portfolioIncluded`는 "현재 포함 여부"만 나타내고 "플랜상 담을 수 있는지" 필드는 아직 없음. 미구현.
- [x] 전용 에러코드로 반환해 프론트가 토스트 문구("포트폴리오 생성 및 추가는 유료 기능이에요")를 띄우게 한다 —
      `PortfolioErrorCode.PRO_PLAN_REQUIRED`, 문구 그대로 일치
